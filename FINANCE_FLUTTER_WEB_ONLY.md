# Finance Flutter — intentional Web-only differences

Only genuine architectural or product-boundary differences. Unfinished Finance features are **not** listed here.

| Web feature | Why it remains Web-only | Architectural / product justification | Other product? | Admin-only? | Desktop-only? | Security? | Already represented in Flutter? | May implement later? |
|---|---|---|---|---|---|---|---|---|
| Payroll, allowances, deductions, bonuses, salary advances, Finance employees | HR/payroll domain rendered inside the Finance Web shell | Independent payroll product. Copying it would merge products. | Yes — HR/Payroll | Payroll permissions | No | No | No — and must not | Only as a separate payroll client |
| Bank statement import / line matching / complete | Operational reconciliation workstation | Matching posts treasury and can affect ledgers. A partial mobile port would be unsafe. Cash/bank balances and transfers are in Flutter. | No | Elevated finance | Intentionally desktop-heavy | Integrity of matching | `/banks` + `/treasury` transfers | Possible later as a dedicated reconciliation UI |
| General ledger journal **create** / chart-of-accounts **editors** | Accounting engine stays on Laravel | Flutter consumes read accounting hub + named reports. Editing journals would duplicate the ledger. | No | `accounting.manage` | Desktop forms | Yes — posting integrity | `/accounting` read, `/reports` | No unless a controlled posting API is designed |
| Product **CMS** (create/edit catalog, variants, website products) | Products product owns the master | Finance Web products page is a **read** of `Product` + sold totals. Flutter matches that read view. | Yes — Products | Products permissions | No | No | `/products` list/detail | Product edits stay in Products |
| Inventory receiving / POS stock ops | Inventory operations belong with Products/POS | Finance lists movements and inventory **valuation report**. | Yes — POS/Products | No | No | No | `/inventory`, inventory-valuation report | No |
| ZATCA certificates, private keys, XML/QR stamping UI, integration secrets | Server-controlled compliance | Flutter must not hold keys or stamp locally. Settings show `zatca_integration_mode` read-only. | No | Finance settings | No | Yes | Read-only mode; `has_qr` on invoices | No |
| Invoice numbering **sequences** and secret payment-provider credentials | Server-owned configuration | Flutter can set prefix / allow-manual flag / footer / color. Sequences stay on Laravel. | No | Settings | No | Yes | Prefix + allow-manual | No |
| Company **logo file** upload | Multipart branding asset on disk | Color/footer/prefix are in Flutter. Logo is a binary settings asset without a Finance v1 upload contract. | No | Settings | Web form | No | Color/footer | Additive upload endpoint later |
| Pixel-identical Blade layout / Alpine invoice builder | Native Flutter client | Feature parity, not HTML clone. | No | No | Web CSS | No | Sectioned RTL desktop forms | No |
| Platform `/notifications` inbox | Platform messaging | Finance **alerts** hub is the Finance notification surface. Inbox/WhatsApp/Instagram/Messenger are other products. | Yes — Inbox | No | No | No | `/alerts` | No |
| Dummy Orders for Finance checkout | Forbidden architecture | Shared billable checkout. GET does not create Payment. POST may create pending checkout. Webhook settles. | Payments | No | No | Settlement integrity | Invoice checkout URL copy/open/refresh | No |
| Recurring expense **scheduler** | Laravel stores `is_recurring` boolean only | No engine to port. Flutter exposes the flag, does not invent recurrence. | No | No | No | No | Recurring flag | Only if Laravel adds a scheduler |
| Web `cashbox` placeholder page | Placeholder, not a product | `ModulePageController::cashbox` is an empty placeholder. Not in the sidebar. | No | No | No | No | Treasury cash accounts | No |
| Web `modules/sales` placeholder | Unused placeholder | Named sales route uses `SalesController`, which Flutter mirrors. | No | No | No | No | `/sales` | No |
| Reports index decorative charts (period-comparison widgets) | Blade visualization of the same services | Named ledger reports + dashboard analytics expose the numbers. Chart chrome is Web presentation. | No | No | Desktop charts | No | Dashboard analytics + `/reports` | Optional chart widgets later |
| Quote **create** multipart attachments | Quote store on Web is multipart; client quote save is JSON | Issued quotes lock. Attachments for **invoices** and **expenses** are implemented. Quote files are not a separate lifecycle on the API. | No | No | No | No | Quote PDF | Additive quote attachment endpoints later |
| Contract **file** attachment upload/download | Web has download/destroy routes; client API has no attachment resource | Contract PDF, schedules, and generated invoices are in Flutter. | No | No | No | No | Contract PDF | Additive attachment endpoints later |
| Phase 10 `/api/finance/v1/invoices` e-invoice contract | Separate compliance surface | Flutter sales invoices use `/sales-invoices` only. | Finance API versions | No | No | Do not break stamp/XML clients | N/A | No |
| POS invoices / cashier orders | Other product | Do not list POS invoices as Finance sales. | Yes — POS/Cashier | No | No | No | No | No |
| Booking | Other product | Independent appointments product. | Yes — Booking | No | No | No | No | No |
| Authoritative tax / totals / balances / ZATCA math in Flutter | Laravel is the calculator | Flutter displays server Money strings and omits line totals from payloads. | No | No | No | Yes | All money fields | No |
